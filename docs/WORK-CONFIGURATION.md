# 规则、电源分析与工作配置

本页描述 V0.3.0 Preview 新增的功能；V0.2.0 及更早安装包不包含这些扩展。

## 专业规则

在「自动触发」编辑规则，可用嵌套的全部 / 任一 / 非条件组，设置优先级、持续满足秒数和冷却秒数。旧版 `combination + conditions` 规则保持原样可读，默认优先级 0、持续 0 秒、冷却 0 秒；有 `expression` 时以表达式为准。

- `all`：任一已知不满足即不满足；否则存在未知即未知。`any`：任一已知满足即满足；否则存在未知即未知。`not unknown` 仍未知。空组不合法。
- 优先级数值高者先选；同级保留旧版后台优先，再按 UUID 字典序排序。输入文件/界面排序不影响赢家。
- 工作会话、手动模式和保护策略继续通过现有协调器优先仲裁。任务请求仍独立参与模式与屏幕需求合并，较弱的规则不会撤销较强的任务需求。
- 持续满足从首次采样匹配开始，恰好达到时长即合格；未知或不满足会重置。通常每 5 秒采样，不是连续硬件监控。超过 15 秒未采样视为连续性丢失，再次匹配重新计时。
- 合格匹配结束后才开始冷却；未知也会结束合格匹配。重复不满足不延长冷却。采样中断时按上次采样后 15 秒失去连续性计算冷却；冷却本身按实际时间流逝。
- 时钟倒退会重置持续窗口并保留剩余冷却。编辑、导入、关闭规则或应用重启会清除运行计时。计时不导出。
- 手动抑制直到条件明确不满足才解除；未知不解除手动抑制。
- 每周时间使用 Mac 当地时区，起点包含、终点不包含；跨午夜归属于开始的星期。夏令时重复小时均参与匹配，不存在的分钟不会被采样。

「只读试运行」展示满足、未满足、未知、持续等待、冷却、抑制与覆盖原因及条件观测。它读取当前观测，在运行计时副本上计算，不保存草稿、不推进真实计时、不登记请求、不切换模式。CLI `rules-try` 使用同一路径。

单条规则最多 64 个叶条件、8 层嵌套；优先级 −1000…1000，持续/冷却 0…86400 秒。规则总数上限 128；可移植文件另受下面的大小和条数限制。

## 电源分析与时间线

「运行记录」新增电源分析。读取公开的 `IOPMCopyAssertionsByProcess`、`IOPMCopyAssertionsStatus`，仅保留 PID、进程名称（`proc_name`）、断言类型和数量。本进程通过 PID 识别；同名外部进程不会冒充 Orexin。本视图不代表辅助服务系统设置的完整清单。

自动采样复用现有 tick，最多每 30 秒一次；只有归一化内容变化才写入现有历史。用户可手动刷新，系统唤醒通知也会刷新。最多读取 128 个进程、512 项断言，优先保留本进程；缺失、部分可读和不支持的类型明确标记未知/不完整。历史摘要保留最多 8 组来源并注明省略数量，展开当前快照可查看其余来源。

时间线沿用最多 200 条本地记录，可连接请求 ID、规则 ID、当时模式、休眠/唤醒通知、显示器、合盖、电源与保护事件。旧记录仍可读，不补造关联。上下文是事件发生时的状态，**不是因果证明**。断言表示请求的行为，不能证明机器实际保持运行，也不能判定真正的唤醒原因。没有系统日志回填；应用未运行期间没有采样。

不读取其他进程参数、断言描述、私有命令输出或系统私有日志。CLI `power` 返回最近快照（首次采样前为 null），`events` 返回最近 50 条时间线；两者不触发采样或清理任务。

## 可复用工作配置

「任务管理 → 工作配置」可创建工作模式、屏幕策略、可选期限和三种结果策略。运行内置命令前选择配置；CLI 用 `--profile UUID`。任务开始时保存配置快照，之后编辑/删除配置不改变已运行任务的模式或期限。

| 结果 | 可配置行为 |
| --- | --- |
| 实际退出 0 | 释放保活，或沿用全部重叠请求成功后 60 秒可取消的休眠；可通知和运行已启用脚本 |
| 正常退出且退出码大于 0 | 释放保活，不请求休眠；可通知和运行已启用脚本 |
| 请求期限/心跳到期 | 释放保活，不推断命令结果；可通知和运行已启用脚本 |
| 用户释放、全局停止、保护覆盖、失联、拒绝 | 不运行结果脚本，不将其归为成功/失败 |

通知使用现有通知能力，不自动申请权限。请求结束、超时或全局停止不终止工作命令。迟到退出码仅记录事实，不重放收尾或脚本。配置不绕过锁屏认证、helper、温度或低电量优先规则。

脚本是本地绝对路径，核验内容后执行该内容的私有临时副本（`/bin/zsh -f`），避免核验后原路径变化执行另一份内容，不执行配置文件内的字符串。列表提供只读内容查看；保存/导入后需明确开启「允许此配置在本机执行上述脚本」。授权绑定配置与各脚本内容摘要，脚本内容变化后失效，且只对授权之后启动的请求生效。导出不带授权；导入会清除涉及配置的本机授权。

脚本 stdin/stdout/stderr 指向 `/dev/null`，不保存输出；环境仅包括系统 PATH、`OREXIN_TASK_ID`、`OREXIN_OUTCOME`、`OREXIN_EXIT_CODE`、原始路径 `OREXIN_SCRIPT_PATH`。`$0` 指向临时副本。需要工作目录的脚本自行 `cd`。最多 4 个并发脚本，每个用单调时钟限制为最多 30 秒；前台脚本结束会清理其进程组，不支持常驻后台工作。全局停止、温度或低电量保护会终止 Orexin 启动的结果脚本进程组，不终止原工作命令。

## 文件格式与导入

UTF-8 JSON，`format = org.orexin.work-configuration`，`version = 1`。根字段只允许 `format`、`version`、`rules`、`profiles`；最多 32 KiB、64 条规则、64 个配置。文件无日期或运行状态，键与星期数组稳定排序，适合 Git。参见 [最小示例](examples/work-configuration.json)。

不包含租约、进程身份、所有者 token、当前手动模式、锁屏/helper/通知权限、脚本授权或凭据。不要在规则名称、路径或自定义脚本中自行放入凭据。

导入完整解码、结构/数值/重复 ID 校验、合并后校验与大小检查均先于应用；任何错误保持原配置不变。预览给出新增/修改/删除列表，以及完整导入前与应用后 JSON。应用前会检查配置是否变化，过期预览不能覆盖后来的编辑。

- **合并**：同 UUID 用导入项替换；已有项保留原位置，新项按 UUID 升序追加。
- **替换全部**：完全使用导入文件中的顺序和内容。
- 两者都会把导入规则设为关闭，并清除导入配置的脚本授权；请在正常规则编辑器和配置列表明确启用。未导入的合并项保持不变。导入不改自动规则总开关。

CLI 示例：

```sh
orexin config-export > orexin-work.json
orexin config-import orexin-work.json --strategy merge
# 审查变化与结果 JSON，再复制输出中的 Preview token
orexin config-import orexin-work.json --strategy merge --apply --expect TOKEN
orexin profiles
orexin run --profile PROFILE-UUID -- /usr/bin/true
orexin rules-try
orexin power
orexin events
```

`--profile` 提供 mode/screen/after，不能同时指定这些覆盖选项；`--timeout` 可进一步缩短期限。现有 v1 操作不变，新增可选 `profileID` 和检查/配置操作。JSON 响应的 `document` 是 Codable Data 的 Base64；解码后为文档 JSON。终端非 JSON 输出直接打印文档。导入 `--apply` 必须携带绑定当前配置及精确结果的预览令牌，没有隐藏脚本启用 API。

## 验证边界

自动化验证使用隔离 UserDefaults、本地 socket 和模拟电源后端，真实执行无害的 CLI/脚本子进程。界面验证使用测试窗口，不替换已安装的 Orexin。公开电源断言只读采样可单独验证。真实休眠、锁屏、合盖、硬件高温/低电量、helper 授权和安装升级不是这些检查的结论。
